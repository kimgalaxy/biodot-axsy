Hermes 공식 문서 확인 · 2026-11-04

헤르메스 공식 문서에서 확인한 기능 가운데 이카운트·플로우·텔레그램 연동에 바로 쓰는 10가지를 골랐습니다. 직접 만드는 것은 이카운트 MCP 서버 하나이고, 나머지는 헤르메스와 플로우가 이미 제공하는 기능을 설정해서 씁니다.

헤르메스 기능문서에서 확인한 내용바이오닷 적용
① MCP 클라이언트stdio·HTTP 서버, 원격 서버 OAuth, 서버별 도구 허용(include)·차단(exclude), 신뢰하지 않는 서버의 쓰기 호출은 확인 요청이카운트 MCP(자체)와 플로우 MCP(공식)를 붙이고, 부서마다 쓸 수 있는 도구를 다르게 설정
② 프로필프로필별 모델·메모리·스킬·시크릿·봇 토큰·크론 분리, 프로필별 게이트웨이 실행경영지원·영업·생산·마케팅·운영실장 5개 프로필 → 전표 입력 권한은 경영지원 프로필에만
③ 텔레그램 토픽·권한토픽별 세션·스킬 지정, 멘션 요구, 관리자·일반 사용자 명령 분리, 허용 사용자 목록부서 그룹의 토픽: 입출고 · 생산 · 전표 · 영업일지 · 중요 알림
④ 크론LLM 없이 스크립트만 실행(출력 없으면 침묵), [SILENT] 규칙, 실패 반복 알림 억제플로우 수집·안전재고 감시는 스크립트 크론(토큰 비용 0), 아침 브리핑·주간 결론은 에이전트 크론

실행 구조 · Admin 광고 운용 화면

매체 API / 보고서→성과·주문·재고 원장→AI 조정안→담당자 승인→공식 API / 관리자 집행→반영 확인 · 재측정

Admin에는 매체별 배정 예산·소진·첫 구매 CPA·ROAS·데이터 시각, 변경 전후 값·근거·승인자·집행 결과를 표시합니다. VM 광고 어댑터는 계정별 권한·한도·중복 차단을 적용하고, 변경 결과가 불명확하면 조회로 확인한 뒤 처리합니다. 크론은 수집·분석을 담당하며 승인 없이 예산을 변경하지 않습니다.

패키지별: Lite는 기본 리포트·담당자 수동 운용, Standard는 매체별 광고 매니저 3명의 분석·운용·캠페인 빌드업과 통합 조정안, Full은 승인 원장과 지원 범위 내 광고 API 연동을 포함하는 구성안입니다. API 접근 전에는 보고서 파일로 같은 지표를 적재합니다. 운영 범위는 광고 운영·전환 추적·매체 전담 3명·퍼포먼스 총괄 직무에 반영하며, 계정·캠페인·소재 수량과 매체별 API 읽기/쓰기 범위는 착수 시 확정합니다. 기존 견적 수치는 유지하고 광고 매체비는 별도로 관리합니다.

공식 확인 자료: Meta Marketing API (접근·권한·지원 범위는 구현 시 확인) · 네이버 검색광고 API · 네이버 성과형 디스플레이 Ad API (Beta) · Google Ads 예산 관리. 상품·계정별 지원 기능과 심사 조건을 확인해 적용합니다.
